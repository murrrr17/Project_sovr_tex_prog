# Документация проекта: Информационная панель мониторинга акций на Flask

## 1. Архитектурный обзор проекта

Данная программная система представляет собой динамический веб-сервис для отслеживания текущих рыночных показателей ключевых российских ценных бумаг («голубых фишек»). Решение реализовано на языке Python с применением микрофреймворка Flask и базируется на классической клиент-серверной модели. Серверная часть координирует обработку маршрутов и агрегацию данных из внешних финансовых систем, в то время как фронтенд отвечает за генерацию адаптивного интерфейса с помощью шаблонизатора Jinja2. Локальная изоляция программных модулей обеспечена средой `venv`, предотвращающей конфликты версий (включая зависимости `Flask`, `requests` и серверные утилиты `Werkzeug`).

Поставщиком информации выступает открытый программный интерфейс Московской Биржи — **MOEX ISS (Information Service System)**. Система запрашивает пакеты данных в формате JSON по торгам в основном режиме (Т+), в реальном времени сопоставляет служебные справочники ценных бумаг с текущими рыночными таблицами, а затем транслирует очищенные агрегированные сведения на сторону пользователя.

Визуальное оформление дашборда спроектировано в соответствии с концепцией **Midnight Glass** (высокотехнологичный темный интерфейс со свойствами матового стекла). Визуальная структура сочетает глубокие темные тона фона, размытие подлежащих слоев (`backdrop-filter`), деликатные неоновые границы информационных блоков и контрастные маркеры ценовых изменений. Это позволяет превратить массивные биржевые таблицы в эстетичный, лаконичный и удобный аналитический инструмент.

### Компоненты системы
Приложение имеет прозрачную модульную структуру:
* **`app.py`** — управляющий скрипт бэкенда, выполняющий сетевое взаимодействие с API, разбор вложенных JSON-структур, вычисление суточных отклонений стоимости активов и распределение веб-запросов.
* **`templates/index.html`** — единый слой представления, объединяющий разметку веб-страницы и каскадные стили Midnight Glass для отображения информационных карточек.

### Принципы проектирования и организация кода
В основу файловой структуры заложен паттерн MVC и концепция разделения сфер ответственности (Separation of Concerns):

1. **Защита окружения:** Выделение зависимостей в виртуальную среду (`python -m venv venv`) изолирует системные пакеты и гарантирует воспроизводимость среды. Файл `.gitignore` исключает конфигурационные данные и кэшированные файлы (`__pycache__/`) из репозитория.
2. **Управление сборкой:** Файл `requirements.txt` фиксирует точные версии библиотек для быстрого развертывания проекта одной командой через пакетный менеджер.
3. **Разграничение уровней системы:** Логика сбора данных (`app.py`) полностью отделена от их визуализации (`templates/index.html`), что упрощает будущую модернизацию интерфейса без вмешательства в алгоритмы бэкенда.
4. **Оптимизация вычислений:** Сопоставление таблиц Мосбиржи реализовано через кэш-таблицы (словари Python) по уникальному идентификатору бумаги (`SECID`). Это гарантирует поиск за константное время O(1) и исключает задержки при рендеринге страниц.

### Методология верификации и тестирования
Стабильность и корректность работы сервиса проверялись по следующим направлениям:
1. **Тестирование интеграции с API MOEX:** Проанализирована структура ответов биржи для безошибочного извлечения индексов динамических столбцов (`LAST`, `CHANGE`, `PREVPRICE`), распределенных по матричной схеме (`columns` и `data`).
2. **Диагностика серверной части:** Активация режима отладки `debug=True` позволила оперативно отловить пограничные состояния данных, включая обработку значений `None` в периоды, когда торги по активу приостановлены.
3. **Проверка адаптивности интерфейса:** Средствами эмуляции мобильных устройств подтверждена гибкость сетки `CSS Grid` — элементы панели корректно подстраиваются под любые экраны, сохраняя читаемость текста.
4. **Анализ отказоустойчивости:** Имитировались сбои сетевого подключения и недоступность удаленных серверов. Блок `try-except` успешно обрабатывает исключения `requests.exceptions.RequestException`, сохраняя работоспособность веб-сервера и выводя пользователю информативное уведомление в общем стиле интерфейса.

## 2. Разработка через промпты: Инструкции для ИИ

Проектирование велось поэтапно, с использованием специализированных запросов к нейросети:

* **Промпт 1 (Парсинг неструктурированного API):**
  > *"Разработай серверную логику на Flask для импорта рыночных данных с Мосбиржи через URL (https://iss.moex.com/iss/engines/stock/markets/shares/boards/TQBR/securities.json?iss.meta=off). Учти, что структура ответа разделена на блоки 'securities' и 'marketdata'. Напиши функцию для динамического поиска индексов полей (SECID, SHORTNAME, PREVPRICE, LAST, CHANGE), объединения этих данных по тикерам и фильтрации списка (оставь только SBER, GAZP, YNDX, LKOH и др.). Предусмотри подстановку PREVPRICE, если текущее значение LAST отсутствует (равно None). Передай итоговый массив в шаблон."*
  * **Обоснование:** Запрос направлен на автоматизацию разбора сложной двухуровневой матрицы ответов MOEX ISS. Он обязывает ИИ создать стабильный алгоритм слияния данных и корректно обработать пустые значения при закрытых торговых сессиях.

* **Промпт 2 (Построение интерфейса Midnight Glass):**
  > *"Создай фронтенд-шаблон index.html на базе Jinja2 для вывода котировок акций. Сверстай адаптивную сетку на CSS Grid. Оформи интерфейс в премиальной темной стилистике 'Midnight Glass': основной фон #0B0F19, blocks с размытием заднего плана backdrop-filter и прозрачными границами. Выдели названия акций крупным полужирным градиентным шрифтом. Реализуй динамическую смену стилей: при росте цены (change >= 0) выводи значение зеленым цветом со знаком ▲, при падении (< 0) — красным цветом со знаком ▼."*
  * **Обоснование:** Данное техническое задание четко регламентирует дизайн системы, превращая обычную страницу в современный трейдинг-терминал. Условия Jinja2 обеспечивают реактивность интерфейса в зависимости от рыночного тренда.

* **Промпт 3 (Повышение отказоустойчивости приложения):**
  > *"Инкапсулируй процесс обращения к API Московской Биржи во Flask в конструкцию try-except для защиты от сетевых сбоев. При возникновении ошибок приложение не должно аварийно завершаться — вместо этого отправь в index.html переменную error с описанием проблемы. Добавь в HTML стильное уведомление об ошибке, оформленное в общей концепции матового стекла."*
  * **Обоснование:** Инструкция направлена на обеспечение высокой доступности (High Availability) веб-ресурса. Сервис изолирует внутренние системные ошибки от пользователя, подменяя их понятным графическим предупреждением.

## 3. Эффективность применения Gemini в проектировании

Использование интеллектуального ассистента значительно сократило цикл разработки и повысило качество кодовой базы:

* **Быстрое освоение закрытых спецификаций:** Сложная матричная структура ответов ISS MOEX обычно требует длительного изучения документации. Нейросеть мгновенно предложила готовое решение для парсинга, минуя ручной разбор JSON-деревьев.
* **Рутинные вычисления «из коробки»:** ИИ без труда взял на себя задачи по математическому округлению котировок до сотых долей, сортировке ценных бумаг по алфавитному порядку и приведению временных меток к единому стандарту.
* **Безупречный фронтенд-код:** Модель сгенерировала валидный CSS-код, содержащий вендорные префиксы (`-webkit-backdrop-filter`), глобальные CSS-переменные (`:root`) для кастомизации палитры и плавные эффекты анимации при взаимодействии с карточками.
* **Масштабируемость архитектуры:** Базовая конфигурация проекта легко поддается расширению. Для добавления на экран новых эмитентов (например, `VTBR`, `AFLT` или `MAGN`) достаточно внесить соответствующие тикеры в массив фильтрации `target_stocks` в `app.py`.
